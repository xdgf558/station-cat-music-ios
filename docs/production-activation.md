# Production activation profile

This change prepares the production client path without enabling a production build or service. All four checked-in build configurations keep native authentication, music, personal sync, and production activation at `NO`; the API origin, public music origin, and encoded activation profile remain empty. Version/build remain 0.1.0 (4). `Production.xcconfig` does not include the Staging/R2 override.

The reviewable template is `Config/ProductionActivation.example.json`. Its identity is fixed to profile `station-native-production-v1`, HTTPS API/public origin `https://wwwstationcat.org`, callback `/auth/mobile/callback`, and application identifier `2AM5S7BM2N.org.stationcat.music`. Its `enabled` field and every capability are false. The origins in this disabled review document do not populate app build settings.

`NativeRuntimeConfiguration` parses the installed bundle once. Production additionally requires an enabled, strict version-1 profile, the exact installed bundle identifier, matching origins/callback/app identity, and independent authentication/music/sync switches. Authentication is required for native services; catalog and playback approvals must agree; sync requires music. Local switches can remove an approved capability but cannot expand the profile. Unknown environments, malformed profiles, extra fields, mismatched identities, and invalid dependencies disable the native stack. Development/Staging reject both `wwwstationcat.org` and `stationcat.org`, including letter-case and trailing-dot variants, so changing only the environment cannot bypass the production profile. The generic `APIClient` remains Mock-only.

Production account deletion is hard-disabled in this profile. The account model creates no deletion service, the view presents no deletion section, and the authentication API rejects reauthentication and all deletion-request routes before sending a request. Staging/development retain the existing isolated deletion path. This does not claim production erasure or retention readiness.

Run `python3 scripts/configure_production.py --check` for an offline, read-only check of the disabled template. The generator's separate `--enable --profile <reviewed-file>` operation accepts only an explicitly enabled profile with the fixed identity and valid capability dependencies; the tracked disabled example is rejected. It writes only ignored `Config/Production.local.xcconfig` and `Config/Production.local.entitlements`. The settings include the profile digest and a base64 representation to preserve JSON through xcconfig expansion; the JSON file, rather than that encoding, is the review artifact. This is configuration validation, not proof of deployment approval, signed provisioning, or AASA readiness. Removing the two generated local files restores the checked-in disabled settings.

The generator has not been used to enable this checkout. Activation still requires a separate deployment decision and verified server resources, migrations, AASA, signing, account flows, and real-device acceptance. Production origin and identity must never be replaced with a pre-release host to test this path: tests use fixture transports plus an in-memory credential store. HTTPS pre-release testing continues to use the separate Staging identity. No production traffic, real account mutation, physical-device installation, or App Store upload is part of these fixture tests.

Local verification on 2026-10-03 used Xcode 27 beta 6 (27A5252f), iPhone 17 Pro simulator / iOS 26.4, UUID `A86B6BE8-D716-4E1D-A731-6F40BAFBB02F`. The initial authentication/music/deletion/profile run passed 59 tests; the startup/scope/core/library/profile run passed 94 tests (with overlap); the final profile run passed all 10 tests after covering production versus isolated catalog notices and rejecting both reserved production hosts across 16 Development/Staging hostname variants before a native stack can be created. The Python generator suite passed 4 tests and disabled-profile/source checks passed. All four final Simulator configurations built successfully; their actual Info.plist files retained all four switches at `NO`, empty API/web/profile fields, and version 0.1.0 (4). These local beta-toolchain results do not claim stable CI, production HTTPS, signed physical-device, or App Store acceptance. Logs are in ignored `evidence/production-ios-*.log`.
