# M5：个人资料库与设置（本地隔离实现）

日期：2026-09-19。承接网站 #176 / iOS #6 的已合并基线。本轮包含个人资料库实现和独立的证据读取 P3 加固；没有部署、开通真实服务、提交 TestFlight 或接入 StoreKit。

## 实现范围

收藏与最近播放按环境、账号分开持久化；游客使用独立文件，不会在登录后自动并入账号。资料库与最近播放入口使用各自列表建立队列。播放记录需要实际音频连续采样累计至少五秒，静音、暂停、拖动造成的进度跳跃不计入；每次播放使用独立事件 ID。最近记录最多 1,000 首、保留 90 天。

账号修改先保存本机操作及幂等 ID，再发送隔离服务。未知结果继续保留同一 ID；服务端使用账号版本 CAS 和原子操作结果，重放不重复写入。收藏冲突保留服务端结果并提示，清空/停用历史通过 epoch 阻止旧离线事件回流。关闭历史另有本机隐私 veto：远端冲突不能偷偷重新开始记录。切换账号或退出取消旧同步，迟到结果不能显示在新账号下。已有网站的浏览器本机收藏没有被迁移；本轮双端实验指两个原生隔离会话。

「我的」新增历史开关、清除记录确认、清理临时缓存、同步状态及隐私/条款/支持入口，四语文案齐全。清理临时缓存清除 URLCache 与当前详情缓存，不删除收藏、历史或凭据。法律链接只用于公开网页导航，不用于认证或媒体 API。

## 存储决策与边界

本轮采用 `ScopedLibrary` actor + 每个作用域一个原子 JSON 文件，而不是规格建议的 SwiftData。这样可以让离线操作日志与显示状态在同一次替换中提交，并直接测试写入失败、未知提交结果、进程重启和账号隔离。文件使用首次解锁后保护并排除系统备份；仅保存个人音乐元数据，不保存 Bearer/refresh token。凭据继续走既有 Keychain。

每个作用域文件最大 20 MiB，待发送操作最多 5,000 条、30 天；单次同步最多处理 100 条，不进行无限自动重试。限制命中会保留已保存状态并报告错误，超龄操作会提示冲突后重新读取服务端。该限制是每个作用域的大小限制，不是全 App 缓存总额；本轮没有完成规格中的独立 150 MiB 图片磁盘缓存或多账号文件总量回收。后续扩大数据规模时需评估 SwiftData 迁移与缓存预算，不应把当前实现描述为这两项已完成。

服务端新增四张 `migrations-mobile` 表，仍与生产迁移目录隔离；销户盘点已分类，执行开关仍关闭。隔离服务保留幂等结果及收藏墓碑，并有每账号操作容量上限；生产启用前必须评审长期压缩/保留策略，不能直接套用当前测试环境保留方式。

网站固定提交 `a5c0ad0bd5e8f8a319f00232a27fc0d8ddcf0990`，来源及关键文件哈希见 `contracts/backend-library-fixture.json`。服务端要求 `MOBILE_PERSONAL_SYNC_ENABLED`、认证、音乐及 isolated 环境门控，并复用原生 Bearer 会话校验。没有向生产 wrangler 配置写入 MOBILE_*、没有接生产 D1/R2。先发布网站分支供 CI 读取，再发布 iOS 分支；旧 M2/M3 探针固定清单保持原样。

## 复审修复：在途隐私操作、并发收藏与事件顺序

本次针对网站 `a00569a` / iOS `2dc2eae` 的四项反馈修复：

- 旧 listen 在请求期间已被清空/关闭操作移出日志时，迟到的 400/404/409 不再拥有日志项，不会删除任何新操作；同步继续处理新的隐私指令。仍存在的失败只删除自身；收藏仅处理同资源、依赖其版本的后续操作，不再删除所有非收藏项。
- 网站将账号 revision 竞争与资源版本冲突分开，最多三次事务尝试，每次重新读取资源版本并验证原生身份，保持原 mutationId。耗尽返回 LIBRARY_BUSY / 503，客户端保留待上传修改；同曲真正版本冲突仍执行服务端优先。
- ListenRequest 必填 occurredAt，直接使用已持久化操作的 created（UTC、毫秒精度）。服务端允许过去 30 天至未来 5 分钟，小幅未来偏差夹到服务器接收时间。新增隔离 0004 迁移保存 received_at；只以更新的发生时间替换同曲历史与位置，相同时间保留已接受记录。旧行只能把原 played_at 回填为接收时间，无法还原历史真实发生时间。
- 快照和有效待传事件按歌曲 ID 取较新记录，然后按事件时间倒序、过滤 90 天并截取 1,000 首。裁剪仅影响展示，不裁掉待上传操作。
