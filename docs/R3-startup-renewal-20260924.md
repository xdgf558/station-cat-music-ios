# R3 真实歌曲起播与续期停顿修复（2026-09-24）

用户报告真实歌曲起播等待十余秒，进度约 42 秒时再次暂停。本轮使用同一 iPhone Air、iOS 27、独立 Staging HTTPS 及《把那年还给风》副本定位和验证；没有修改生产服务、服务器授权期限、账户资料、支付或 App Store 状态。

## 原因与调整

客户端原来以 64 KiB 顺序请求音频，同时重复请求 HEAD。真实 MP3 的 ID3 区段包含内嵌封面，7 首曲目的标签约 29–484 KB；测试歌曲约 317 KB。真机记录单次媒体请求常需约 1.6 秒，解析标签就需要多轮往返。AVPlayer 默认缓冲预测也不适用于提供音频字节的自定义 AVAssetResourceLoader；本机 Apple SDK 的 AVPlayer.h 明确要求此情况关闭 automaticallyWaitsToMinimizeStalling。

原续期流程每次都创建新 AVPlayerItem、重新读取和解析 MP3，再 seek 到当前时间。按墙钟续期时，起播等待已经消耗十余秒，因此用户可能在约 42 秒的媒体进度处遇到重新缓冲。诊断中成功获得两次授权，没有证据表明这次停顿由拒绝播放资格导致。

- 使用明确上限的 512 KiB Range，首个 Range 同时取得长度和音频前缀，省去独立 HEAD 和两字节探测往返。只在该授权通道的 RAM 中保留最多 512 KiB 前缀；不落盘，不跨授权共享，不构成离线歌曲缓存。缓存读取仍检查取消、账号作用域、凭据和连续时钟截止。
- 续期先取得新授权，再用新通道 HEAD 核验对象。仅在账号、会话/epoch、歌曲、音频版本、variant、时长、预览偏移、ETag 和长度均一致时更换后续请求通道，保留现有 AVPlayerItem 和进度，不再次激活音频会话或 seek。
- 跨越通道切换的旧 Range 结果丢弃，只在同一偏移使用已确认的新授权重读一次。暂停、切歌、退出和取消仍关闭 loader。续期前后再次检查旧截止时间，迟到结果不能恢复已经停止的播放。
- 继续保留五秒媒体请求预算、一次 401 凭据刷新、HTTPS/重定向限制、服务端重验节奏和硬截止；没有增加授权失败后的自动重播。
