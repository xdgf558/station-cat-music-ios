# “我的”入口闪退修复 · 1.0.9（22）

1.0.8（21）在 iPhone 16 / iOS 27.0.1 上，点击“我的”会退出。手机上三份报告的镜像 UUID 均与该发行归档的 dSYM 匹配：主线程落入栈保护页，Swift 运行时反复解析泛型元数据。符号化定位到 `RootView.library` 的设置目的页闭包，经 `NavigationLink` 从 `PlatformLibraryHome.settingsRows` 构造。它发生在显示设置入口时，不需要点击某个设置页。

四个复杂目的页此前由 ViewBuilder 合成一个多层 `_ConditionalContent`。现在设置闭包明确返回 `AnyView`，每个分支分别转换，使构造入口时不再解析那一个组合大类型。设置内容、数据存储格式与收听逻辑均未修改。

本机验证使用 Xcode 27.2。先用原发行源码与正式优化配置在 iOS 27.0 模拟器测试，空资料和合成旧收藏、最近查看、手记均能打开“我的”；因此这些模拟器通过结果不能否定手机报告，也不能单独证明这次修复。

真机对照使用独立的开发签名 QA App，沿用已有 Staging 标识和签名，以 Production `-O` 编译，所有远端服务保持关闭。未注册新 App ID 或设备，未替换手机上的正式 App。相同的 UI 驱动在修复前点击“我的”后捕获相同的泛型元数据崩溃（1 项执行、1 项失败）；修复后检查“我的”、语言、隐私、关于及切换 Tab 返回，结果为 1 项执行、1 项通过、0 失败、0 跳过。临时 QA App 与运行器已清理，正式 App 读回仍为 1.0.8（21）。

新增独立 `StationCatMusicProductionNavigation` scheme，以正式优化配置检查纸色、深夜、三个设置入口、Tab 返回及冷重开。原有 PublicLinks 验收范围保持不变。CI 校验实际产物的关闭态配置，并要求该回归执行 1 项、通过 1 项，失败与跳过都为 0。旧原生音源专用验收继续仅手动运行。

新增自动化首次运行在第二次启动时未离开启动页。保留的 AX 证据显示预点击快照仍属于上一轮已终止进程，而事件目标已是新进程；它没有发生“我的”崩溃。驱动改为每次冷启动建立新的 `XCUIApplication`、确认前台和按钮可点击，不增加 sleep 或重试。修正后的独立回归执行 1 项、通过 1 项、0 失败、0 跳过；原失败记录保留。
