# R1 — 原生销户回执与本机资料清理

2026-10-02。本批沿用既有 prepare / confirm / receipt-only status 接口，不启用生产原生配置、不修改认证、音频、版本号，也不安装实体手机或上传 App。版本仍为 0.1.0 (4)，已保留该分支原有的更新说明和用户确认离线验收提交。

## 回执与进度

客户端仅根据经过校验的服务端结果显示删除完成。completed 必须 confirmAccepted=true，stage=completed，确认时间早于原准备期限，且 confirmedAt ≤ completedAt ≤ serverNow；非完成状态不得携带完成时间。原 receiptExpiresAt、已记录的 confirmedAt 和 completedAt 不得被迟到响应延长或改写。未知状态、错误请求 ID、未来时间、不一致确认或完成时间、无效完成字段均拒绝，原 Keychain 凭据与日志保持不变，用户仍可继续查询。

查询进度只发送 DeletionReceipt GET，没有 Bearer、Cookie 或自动确认/刷新。请求串行化，已确认的 completed/preparation_expired 不会被迟到响应改回在途状态。阶段只映射已知四语文案，未知阶段不直接显示服务端文本。

DeletionJournal 在同一个原子 Keychain item 中保存当前申请与已验证终态归档。旧 envelope 自动兼容读取。只有服务端已经验证 completed 或 preparation_expired，才允许下一次明确申请生成新的 ID 和 receipt；原在途或确认结果未知的申请继续保留原 ID，不能用新账号覆盖。归档写入与新申请写入一起成功，存储失败不会失去原回执。

账号与安全页提供“先前的删除申请”，展示完成/确认时间、查询有效期和请求编号短摘要；点击可在登出后查询旧回执。界面不暴露 receipt 原文、邮箱或其他账号身份。归档目前不自动删除，长期容量和保留期限属于后续政策边界；本批尤其不根据本机时间删除未完成或确认结果未知的回执。

## 本机清理

只有已验证服务端确认的申请才清理对应 environment/account 的 PersonalMusic 私有文件，并建立本进程的作用域写入屏障。在途同步返回、迟到写入或播放事件不能重建已删除文件。游客、其他账号、其他环境、公共歌曲缓存和其他文件保留；Keychain 删除回执独立保留。

文件清理或确认标记写入失败时显示“尚未清理完成”，保留可重试状态。重新启动、再次查询进度时重新建立屏障并重试本机清理；即使网络不可用或回执查询过期，已经持久化确认的本机清理仍可执行。服务器账号完成与本机文件清理使用分开的文案，避免把单方结果当成全部完成。

应用重启依靠已确认回执重新建立本机屏障。其他设备、外部服务、备份和生产数据库的清理结果仍由服务端完整生命周期验收负责，本客户端改动不能替代它们。公开评论匿名保留、余额/争议单独处理且不自动退款或清零的说明沿用用户已确认规则。

旧 envelope 缺少 confirmedAt 时，仅凭 confirmAttempted 不能认定服务端已确认。若升级前从未持久化正向回执，且服务端查询已超过 14 天，继续保留结果未知日志和本机资料，等待后续人工/政策恢复；旧格式可读取不表示这类情况可以自动完成清理。

## 本机验证

使用 Xcode 27 beta 6、指定 iPhone 模拟器，未触碰实体手机。最新局部测试结果见 `.build/r1-deletion-tests-terminal.xcresult` 与 `.build/r1-deletion-tests-terminal.log`：69/69 通过，包括 16 项本批销户生命周期测试、30 项 Core、8 项本机账号清理、15 项既有认证回归。范围包括严格时间/状态、错误响应保持原回执、终态原子归档、旧格式迁移、不同账号下一申请、归档查询、精确私有文件清理、损坏/符号链接拒绝、离线新客户端重开、在途同步清理屏障及既有认证/核心/清理回归。

OpenAPI 校验通过：26 个操作、67 个正例、21 个反例；四语资源和源码边界守卫通过。当前没有为模拟器注入认证产品配置来截图归档入口，归档按钮和布局已由产品编译检查，列表/选择/receipt-only 查询模型由确定性测试执行。完整远端固定工具链、真实 Keychain 锁定和实体机仍须后续验收，不沿用旧结果宣称本轮已通过。
